#+TITLE: Majutsu NEWS -- History of notable and user-visible changes
#+AUTHOR: 0WD0

* [Unreleased]

** Breaking changes

- Requirements ::
  Majutsu needs Jujutsu 0.47.0, Magit 4.4.0 and Transient 0.13.0 or later.
  Compat 31.0.0.1, Consult 1.0 and plz 0.9.1 are new dependencies.

- ~RET~ shows a diff ::
  ~RET~ on a revision, bookmark or tag shows its diff; it used to run
  =jj edit=, which is rarely what a look at a revision calls for and
  silently redirects later changes into that revision.  ~e~ edits.  ~D~,
  which showed the same diff, is gone, also from the dispatcher and the
  Embark maps.

- Renamed commands and options ::
  The edit-at-point command is ~majutsu-edit~; sequential log navigation is
  ~majutsu-goto-next-revision~ and ~majutsu-goto-prev-revision~.
  ~majutsu-edit-finish-on-save~ is ~majutsu-diffedit-finish-on-save~.
  The old names have no aliases; built-in keys are unchanged.  Prompts and
  help follow jj's terms: a new /change/, a selected /revision/.

- Removed commands and options ::
  | Removed                             | Use instead                                     |
  |-------------------------------------+-------------------------------------------------|
  | ~majutsu-diff-refresh~              | ~d~ in the Diff transient, ~g~ in a diff buffer |
  | ~majutsu-find-file-at-point~        | ~majutsu-find-file~                             |
  | ~majutsu-enter-dwim~                | ~majutsu-visit-thing~                           |
  | ~majutsu-diff-resolve-conflict~     | ~E m~ / ~E M~ in the Ediff transient            |
  | ~majutsu-duplicate-dwim~, ~y~ / ~Y~ | ~? y~                                           |
  | ~majutsu-diff-refine-max-chars~     | nothing; refinement no longer skips large hunks |
  | ~majutsu-log-field-faces~           | ~:face~ of each log column                      |
  | Squash =-r/--revision=              | =-f/--from=                                     |
  | =--fetch-tags= (removed from jj)    | =--tag= when cloning                            |
  | Log column ~git-head~               | nothing; jj dropped =git_head=                  |
  The dispatcher's ~m~ now opens Metaedit, and diff file sections no longer
  bind ~v~.

- Log columns ::
  ~majutsu-log-commit-columns~ has a new format: ~:module~ (~heading~, ~tail~,
  ~body~ or ~metadata~) replaces ~:align~ / ~:visible~, and columns take
  ~:template~, ~:face~ and ~:post~.  A ~:post~ function must keep the number
  of displayed lines and whether the field is empty; changes of layout belong
  in ~:template~.

- Saved transient defaults ::
  ~w~ opens a transient: ~w u~ saves user defaults, ~w r~ repository defaults and
  ~w w~ workspace defaults; the uppercase keys clear them.  This replaces the
  standalone ~w~ / ~W~ actions.  Existing saved values remain readable.
  Buffers no longer reuse options across workspaces, and ~0~ in the log resets
  the current options without deleting saved defaults.

** Added

*** Views

- Bookmark list and remote list ::
  Both were raw jj output.  ~majutsu-bookmark-list~ lists the local bookmarks;
  each shows the state of its remotes on its line and unfolds to its remote
  bookmarks, and =@git= appears only when it differs.  Conflicted bookmarks
  unfold to their targets.  ~majutsu-git-remote-list~ lists the remotes with
  their URLs; each unfolds to the bookmarks it holds, including those that
  exist only there.  Either command moves to the counterpart of the bookmark
  or remote at point.  ~majutsu-bookmark-list-columns~ customizes the rows.

- Operation history ::
  ~majutsu-op-transient~ (~X~) offers the operation log, diff, restore and
  revert.  The log keeps jj's compact graph; an operation diff shows the two
  operations and the changed commits, and ~RET~ on one opens its evolution.

- Evolution history ::
  ~majutsu-evolog~ (~v~) shows earlier versions of a change.  ~RET~ displays
  jj's inter-diff against that version's predecessors.

- Tags ::
  ~majutsu-tag~ (~t~) lists, creates, moves and deletes tags.

- Text conflict workbench ::
  ~? M~ lists a revision's conflicted files as a directory tree.
  Files unfold into conflict blocks with diff previews, and ~RET~ opens a
  private draft at that block.  Saving a draft leaves jj untouched; applying
  writes the file, or every draft below a directory, in one operation.  A
  failed or unverified write keeps the drafts.  ~?~ lists the actions
  (~C-c ?~ in a draft).  The Ediff commands remain available.

- Revision information in diff buffers ::
  The diff of one revision starts with its metadata and full description,
  both collapsible.  Comparisons with =--from= / =--to= show none.

- Syntax highlighting in diffs ::
  ~T~ toggles highlighting inside hunks; ~majutsu-diff-fontify-hunk~ chooses
  the current hunk or all of them.  Experimental, and slow on large diffs.

- Aligned log tails ::
  Long descriptions are cut with … so that ids, authors and dates stay
  right-aligned.  Only the display is cut: copying and editing in place see
  the whole text.  ~majutsu-log-elide-description~ turns it off.

- Navigation and copying ::
  ~[~ and ~]~ in the log jump to visible parents and children.  The log,
  evolution log and operation log share a ~? w~ transient that copies displayed
  text or whole fields, including ids that are not displayed.

- Blob buffers elsewhere ::
  ~majutsu-find-file-other-window~ and ~majutsu-find-file-other-frame~.

*** Commands

- Sign, Revert, Metaedit, Simplify Parents ::
  New transients for =jj sign= / =unsign= (with signing-key completion for
  GPG, GPGSM and SSH), =jj revert=, =jj metaedit= and =jj simplify-parents=.

- Bookmark advance ::
  ~majutsu-bookmark-advance~ runs =jj bookmark advance= with a target
  revision and bookmark names or patterns.

- jj's Arrange TUI ::
  ~majutsu-arrange-tui~ (~? A~) runs =jj arrange= in Ghostel.  It uses jj's
  =revsets.arrange= unless a prefix argument asks for a revset.

- Any jj or shell command ::
  ~majutsu-command~ (~!~) runs a command asynchronously, in the current
  directory or the workspace root, and shows its output in the process
  buffer.  ~TAB~ completes jj commands.

- Completion from jj ::
  Revset prompts complete whole expressions with jj's own candidates for the
  command at hand.

- Gerrit uploads ::
  The Git transient offers =jj gerrit upload= with revisions, remote branch,
  review metadata and repository-local defaults.  Reviewer, CC and topic
  prompts complete against Gerrit.

- More options ::
  Squash =--use-destination-message=, Rebase =--simplify-parents=, repeated
  Absorb =--into=, and Revert =--insert-after= with =--insert-before=.
  Fetch and Push select tags with =--tag=; Fetch remotes and branches, Clone
  branches and tags, and Push =--option= can be repeated; Remote add takes
  =--push-url=.  Split and Squash also run on ~RET~.

*** Patch selections and diff editors

- Whole files ::
  ~F~ selects a whole file, including binary and other changes without
  hunks, for Split, Squash and Restore.

- Absorb ::
  Absorb takes ~H~ / ~F~ / ~R~ selections from the diff of one revision.  jj
  assigns the selected changes to ancestors; the rest stays in the source.

- jj's diff editors ::
  Split, Squash, Absorb and Restore honor =--interactive= and =--tool=, which
  take precedence over an Emacs selection.  Split also opens the editor when
  it has neither a selection nor a fileset.

- Terminal diff editors ::
  With Ghostel, jj's built-in terminal diff editor runs inside Emacs, locally
  and over POSIX TRAMP connections.  ~majutsu-diff-editor-host~ selects the
  host; tools that need no terminal run without Ghostel.

*** Integrations

- TRAMP ::
  Majutsu runs jj and opens revision files in remote workspaces, Ediff and
  description editing included.  ~majutsu-remote-jj-executable~ names the
  remote executable; ~majutsu-jj-environment~ applies locally and remotely.

- Forge ::
  ~majutsu-forge-mode~ shows Forge pull requests, issues and discussions in
  the log and binds the Forge commands.  Meant for colocated repositories.

- Embark ::
  Embark acts on bookmarks, revisions and remotes in Majutsu buffers and on
  bookmark and workspace completion candidates: inspect, move, rename,
  track, fetch, visit.  The default action shows a diff; editing is an
  explicit action.

- Org links ::
  ~org-store-link~ in a Majutsu buffer stores a =majutsu-rev:= link to the
  revision at point, or a =majutsu:= link to the repository.

- Bug references ::
  Log and description buffers enable ~bug-reference-mode~ and can derive the
  issue links from the repository's Git remotes.

*** Editing

- Descriptions in place ::
  ~w~ (~i~ in Evil) in the log, or above the diff of one revision, makes
  the descriptions editable where they are shown, like Wdired.  ~C-c C-c~
  applies every changed description in one =jj describe=.

- Description buffers ::
  Description buffers save, recall and search earlier messages, and
  ~C-c C-d~ shows the diff being described.  Summary text beyond column 68
  is highlighted and the body fills at column 72
  (~majutsu-jjdescription-summary-max-length~,
  ~majutsu-jjdescription-fill-column~; nil disables either).

- Conflict markers ::
  Sides have their own backgrounds, Eldoc help and a context menu.  New
  commands keep the term at point, concatenate the sides (asking first when
  the base is not empty) and switch marker styles.  Resolving the last
  conflict leaves the mode and undo returns to it; see
  ~majutsu-conflict-auto-leave~.

- Workspaces ::
  ~majutsu-workspace-remove~ (~k~ in the Workspace transient) runs
  =jj workspace remove=: jj snapshots the working copy into a commit and
  deletes the directory.

- Template DSL ::
  Anonymous functions, the ~[:|arg| body]~ form, and syntax forms defined
  with ~majutsu-template-defspecial~.

** Changed

- Log graph ::
  Multiline descriptions are part of jj's graph, and folding a revision
  hides its body without running jj again.  Elided-revision markers and
  other lines between revisions are decorations: point skips them, and they
  are not searched, copied or folded.

- Conflicts section ::
  ~majutsu-log-insert-conflicts~, an optional log section, groups the
  conflicted files into collapsible directories and shows how many sides
  each has, including conflicts a merge inherited.

- Revision prompts ::
  The log's revset filter is an ordinary =-r= argument, and empty input
  clears it.  Revision prompts prefer the reference at point.

- Fileset prompts ::
  The =--= entries read fileset expressions.  Completion applies to the
  path being typed inside an expression and offers pattern kinds such as
  =glob:=; commas inside quotes no longer split a pattern.  Diff, Split,
  Squash, Absorb and Restore complete the paths their revisions change,
  and Log completes one directory level at a time.  The whole repository
  is no longer listed, which took seconds in a large one.

- Diffs from a limited log ::
  A diff opened from a log that is limited to filesets has the same limit,
  whether through ~RET~ or the Diff transient, where it can be removed.

- Evil ::
  Blob buffers keep the normal text motions and paste: ~gj~ / ~gk~ (or
  ~C-j~ / ~C-k~) move between revisions, ~gb~ annotates, ~gf~ visits the
  workspace file and ~gr~ reverts.  The dispatcher shows the Evil keys, and
  diff context uses ~+~, ~=~ and =~=.

- Restore ::
  A Restore without arguments asks before discarding every working-copy
  change, and honors ~majutsu-no-confirm~ and ~majutsu-slow-confirm~.

** Fixed

- Defaults of Split, Squash, Restore and Duplicate ::
  Split and Restore use the revision at point.  Squash keeps the source it
  was opened on when only a destination is given; an arbitrary comparison
  implies none.  Duplicate takes revisions from the region, not file names.
  Prompts and actions use the buffer that opened the transient.

- Patch selections ::
  Concurrent operations no longer overwrite each other's patch.  A stale
  selection, or one from a diff other than the displayed one, is rejected.
  A cancelled editor session keeps the selection.  Binary contents and the
  executable bit are selected separately.  Partial selections no longer
  join text onto an unselected last line that lacks a newline, and Restore
  keeps unselected changes in other files.

- Conflict resolution ::
  Keep-side numbers match jj's labels and keep-base takes the real base.
  Quitting Ediff without edits leaves the conflict; saving a merge asks
  first and keeps unresolved markers.  Conflicts in a revision other than
  the working copy open as editable blobs, and saving resolves them there.

- Divergent changes ::
  Blob editing, history navigation and annotation use commit ids, and
  saving follows the rewrite that save produced.  A save that cannot be
  verified keeps the edits in the buffer.

- jj warnings ::
  A warning that jj prints with every command, such as one about a
  deprecated setting, no longer leaves every Majutsu buffer empty.

- Paths ::
  File names with spaces or fileset metacharacters work in conflict
  discovery and diffedit; workspace paths may contain control characters.

- Display ::
  Permission changes show both modes.  Collapsed sections no longer join
  adjacent headings, refreshes during a rebuild no longer corrupt the
  buffer, and =jj new= refreshes the buffer it was run from.  Text that
  looks like a patch in a description stays text.

- Evil log keys ::
  ~[~ and ~]~ work when a global Evil minor mode, such as
  ~evil-collection-unimpaired-mode~, claims them as prefixes.

- GPG prompts ::
  Emacs pinentry prompts can be answered while jj waits.

* [0.5.0] - 2026-01-09
